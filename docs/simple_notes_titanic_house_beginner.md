# Простой конспект (Beginner): Titanic + House Prices

Этот файл сделан максимально простым языком.
Цель: чтобы ты смог(ла) уверенно объяснить проект на 1:1 и сам(а) запустить EDA.

## 1. Быстрый словарь (без сложных слов)

- `artifact` (артефакт): любой сохраненный результат запуска.
  - Примеры: `cv_scores.csv`, `submission.csv`, `train_summary.json`, графики EDA.
- `артефакт трейна` в плохом смысле: случайный эффект данных/сплита, который выглядит как "улучшение", но не повторяется.
- `anti-artifact` (по смыслу): проверка, что улучшение не случайное.
  - Пример: одинаковая схема валидации, повторяемость на фолдах, нет leakage.
- `leakage` (утечка): когда модель случайно получает информацию о будущем/таргете и метрика искусственно завышается.
- `baseline`: простая и понятная стартовая модель, от которой сравниваем все улучшения.
- `trade-off`: что выиграли и что потеряли из-за выбранного решения.

## 2. Как отвечать на 1:1 (очень простой шаблон)

На любой вопрос отвечай по формуле:

1. Что была за цель.
2. Что ты сделал(а).
3. Какая была альтернатива.
4. Какой минус у твоего варианта.
5. Как ты этот риск проверил(а).

Короткий шаблон фразы:

"Цель была X. Я выбрал(а) Y, потому что Z. Альтернатива была A. Минус Y: B. Я это контролировал(а) через C."

## 3. Titanic: что важно сказать простыми словами

- Это задача бинарной классификации: выжил/не выжил.
- Сначала нужен честный baseline (простые и понятные модели).
- Потом можно включать более сильные подходы (например, WCG-ветку), но аккуратно, чтобы не было утечки.
- Главная мысль: не гнаться за цифрой любой ценой, а показывать воспроизводимый и понятный процесс.

Что показать в репозитории:

- `artifacts/reports/cv_scores.csv` — сравнение моделей.
- `artifacts/reports/wcg_tuning_summary.json` — что тюнили и с какими весами бленда.
- `docs/titanic_rationale.md` — почему так устроен пайплайн.

## 4. House Prices: что важно сказать простыми словами

- Это регрессия: предсказываем `SalePrice`.
- Часто используем `log1p(SalePrice)`, потому что цены сильно скошены.
- Нужен baseline + единая схема CV, чтобы сравнение моделей было честным.
- Главное: показать, что улучшения стабильны, а не случайны.

Что показать в репозитории:

- `artifacts/reports/cv_scores.csv` — сравнение RMSE(log).
- `artifacts/reports/feature_summary.json` — сводка по признакам.
- `README.md` — итоговые метрики и запуск.

## 5. Готовые короткие ответы (можно почти выучить)

### "Почему такой baseline?"
"Я выбрал(а) baseline, который легко объяснить и повторить. Так видно, есть ли вообще сигнал в данных, и от чего реально растет метрика."

### "Что делали против leakage?"
"Использовал(а) честную схему валидации и проверял(а), чтобы фичи не подглядывали в target из validation/test."

### "Зачем сложные модели?"
"Чтобы проверить верхнюю планку качества. Но сравнение делал(а) только через одну и ту же схему CV, иначе выводы будут нечестными."

### "Что было самым сложным?"
"Убедиться, что улучшение не случайное: один красивый запуск ничего не значит, важна стабильность по фолдам."

## 6. Как запустить EDA ноутбуки (пошагово)

Ниже два варианта: через VS Code (проще) и через терминал.

### Вариант A: VS Code (рекомендуется)

1. Открой папку проекта:
   - Titanic: `~/titanic_project`
   - House Prices: `~/house_prices_kaggle`
2. Открой файл:
   - `notebooks/eda.ipynb`
3. В правом верхнем углу выбери Kernel:
   - Python из `.venv` этого проекта.
4. Нажми `Run All`.
5. Если попросит установить расширения, установи `Python` и `Jupyter`.

Если ошибка "package not found":

```bash
cd ~/titanic_project
source .venv/bin/activate
pip install -r requirements.txt
```

Для House Prices:

```bash
cd ~/house_prices_kaggle
source .venv/bin/activate
pip install -r requirements.txt
```

### Вариант B: Через Jupyter Lab из терминала

Titanic:

```bash
cd ~/titanic_project
source .venv/bin/activate
python -m jupyter lab
```

House Prices:

```bash
cd ~/house_prices_kaggle
source .venv/bin/activate
python -m jupyter lab
```

Потом в браузере открой `notebooks/eda.ipynb` и запусти `Run All`.
